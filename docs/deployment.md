# Установка и сопровождение

## Существующая PostgreSQL

Для разработки достаточно `main.py`. Если нужно использовать уже созданную БД,
создайте отдельные базу и пользователя средствами PostgreSQL, скопируйте `.env.example`
в `.env`, заполните реквизиты и секрет Django. Установите `NORDSEC_LOCAL_CLUSTER=0`.
Пользователю тестовой установки требуется право CREATEDB для тестов Django.
Рабочему пользователю это право не требуется.

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe manage.py migrate
.venv\Scripts\python.exe manage.py createsuperuser
.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

Такой запуск предназначен для разработки. Для ручных команд локальный кластер
должен работать; его можно запустить через `main.py` в другом окне.

## Рабочая установка

Используйте отдельную пустую базу без демонстрационных аккаунтов. Укажите
`DJANGO_DEBUG=0`, `NORDSEC_DEMO=0`, случайный `DJANGO_SECRET_KEY`, точный домен
в `DJANGO_ALLOWED_HOSTS`, адрес с HTTPS в `DJANGO_CSRF_TRUSTED_ORIGINS`.
Настройте HTTPS reverse proxy с действующим сертификатом, пересылающий запросы
на **127.0.0.1:8080** с сохранением Host. Установите `NORDSEC_BEHIND_HTTPS_PROXY=1`.
Waitress слушает только loopback; TLS завершается на reverse proxy.

```powershell
.venv\Scripts\python.exe manage.py migrate --noinput
.venv\Scripts\python.exe manage.py collectstatic --noinput
.venv\Scripts\python.exe manage.py check --deploy
.venv\Scripts\python.exe -m scripts.serve --port 8080
```

В отдельном управляемом процессе:

```powershell
.venv\Scripts\python.exe manage.py expire_reservations --loop
```

Либо запускайте `expire_reservations` раз в минуту через планировщик.
Настройте перезапуск обоих процессов при сбоях. Не публикуйте `.env`, `.runtime`,
`backups` или `media` как статические каталоги. WhiteNoise обслуживает только
`staticfiles`; доступ к фото остаётся в Django. Сайт не содержит публичной загрузки документов.

HTTPS-размещение и внешний домен в рамках локальной проверки не настраивались.
До эксплуатации согласуйте с фондом роли сотрудников, условия приёма вещей,
регламент выдачи, основания и сроки обработки данных. Текст страницы обработки данных
в проекте описывает учебную демонстрацию и требует согласования для реальной установки.

## Резервные копии

При работающей базе:

```powershell
.venv\Scripts\python.exe scripts\backup.py
```

В `backups` сохраняются PostgreSQL dump и ZIP с фотографиями. `.env` храните отдельно.
Копии содержат закрытые данные; доступ к ним ограничьте ответственными сотрудниками.
Срок и периодичность хранения определяются регламентом фонда.

Для проверки восстановления создайте **новую пустую базу** и используйте
`pg_restore` из того же или более нового PostgreSQL. Пример для локальной установки:

```powershell
& 'C:\Program Files\PostgreSQL\18\bin\createdb.exe' -h 127.0.0.1 -p 55432 -U nordsec nordsec_restore_check
& 'C:\Program Files\PostgreSQL\18\bin\pg_restore.exe' -h 127.0.0.1 -p 55432 -U nordsec -d nordsec_restore_check --no-owner 'backups\ИМЯ_КОПИИ.dump'
```

Пароль вводится по запросу. Распакуйте ZIP фотографий в отдельную проверочную
копию проекта с сохранением папки `media`. Укажите проверочную БД в её `.env`
и проверьте вход, карточки с фото и отчёт. Не восстанавливайте поверх текущей рабочей базы.

## Частые проблемы

- PostgreSQL не найден: установите PostgreSQL 14+ или задайте переменную `PG_BIN`
  с путём к его папке `bin`. Автоматический локальный запуск рассчитан на Windows.
- Порт 8000 занят: закройте предыдущий запуск или используйте `--port 8001`.
- База недоступна: проверьте запущен ли кластер и соответствуют ли реквизиты `.env`.
- Хотите чистую рабочую установку после демонстрации: используйте новую БД,
  `NORDSEC_DEMO=0` и новые учётные записи. Не переносите демонстрационные аккаунты.
- Основной сайт фонда недоступен: локальный интерфейс продолжает работать,
  поскольку стили, иллюстрации и логотип находятся в проекте.
