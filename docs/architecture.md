# Архитектура NordSec

Приложение построено как единый проект Django с PostgreSQL. Браузер получает
готовые страницы. Изменения выполняются через POST-формы с CSRF-защитой.
Авторизация основана на сессиях Django. Основная логика собрана в `apps/aid/services.py`;
страницы вызывают её после проверки формы. Административная панель не позволяет
напрямую менять состояния рабочих записей.

## Состав данных

- `User` — участник, контактные данные и роль.
- `Category` — справочник категорий вещей.
- `Item` — предложение и последующая учётная карточка одной вещи/комплекта.
- `HelpRequest` — обращение получателя и решение координатора.
- `Reservation` — связь обращения с вещью, срок и условия передачи.
- `VolunteerApplication` — заявка на участие в волонтёрской работе.
- `VolunteerTask` — поручение по конкретному резерву.
- `Transfer` — подтверждённая выдача и, при необходимости, запись её исправления.
- `AuditLog`, `Notification`, `Favorite`, `LoginAttempt` — журнал, уведомления,
  избранное и ограничение попыток входа.

У одного резерва не больше одного поручения и одной записи выдачи. В базе
действуют частичные уникальные ограничения: одна вещь и одно обращение не могут
одновременно участвовать в нескольких активных резервах. Закрытые резервы сохраняются.

## Порядок операций

Предложение → проверка координатором → доступная вещь → одобренное обращение →
резерв → прямая передача или поручение волонтёру → подтверждение выдачи.

Основные операции выполняются в транзакциях. Порядок блокировок связанных строк:
вещь → обращение → резерв → поручение. Конкурентный тест запускает двух координаторов
в отдельных соединениях PostgreSQL и проверяет, что только один получает вещь.

Статус вещи отражает этап обработки; местонахождение — отдельный физический факт.
После старта доставки вещь находится у волонтёра, после отметки доставки — у получателя,
но выдача ещё не считается подтверждённой. Подтверждение выполняет координатор.
Исправление выдачи сохраняет исходную запись, причину, сотрудника и время исправления.

Просроченный резерв освобождается только для вещи, оставшейся у жертвователя
или в фонде. Если вещь перемещена, резерв сохраняется и координатор получает
уведомление для проверки. Отмена после перемещения требует подтверждения возврата.

## Доступ

Гость видит каталог и описание проекта. Участник создаёт свои предложения
и обращения, просматривает их состояние и уведомления. Волонтёр дополнительно
видит открытые и собственные поручения. Точные контакты маршрута открываются
назначенному волонтёру после принятия поручения. Координатор работает со всеми
обращениями, предложениями, резервами и отчётами. Суперпользователь имеет также
техническую панель управления пользователями и справочниками.

Проверки выполняются на сервере, в том числе при прямом открытии адреса записи.
Фотографии выдаются через проверку доступа, а не открытый каталог `media`.
В публичном каталоге нет полей с нуждаемостью получателя, телефонами и точными адресами.

## Интерфейс и сопровождение

Общие элементы находятся в `templates/includes`. CSS и JavaScript не требуют
внешних CDN. Логотип фонда хранится локально; иллюстрации категорий — локальные SVG.
WhiteNoise раздаёт собранные статические файлы при рабочем запуске через Waitress.
Пользовательские фотографии через WhiteNoise не раздаются.

Счётчики отчёта разделяют предложения, принятые вещи, обращения и фактические
выдачи. Дата выдачи переводится в часовой пояс Красноярска. CSV содержит одну строку
на неисправленную выдачу, строки защищены от интерпретации формул табличным редактором.
