# NordSec

Система учёта и передачи вещевой помощи для благотворительного фонда
«Территория добра», Норильск. Python + Django + PostgreSQL, серверные HTML-шаблоны,
CSS и JavaScript. Flask и отдельный сервер интерфейса не нужны.

## Запуск в PyCharm

1. Откройте **C:\Users\golob\PycharmProjects\NordSec** как проект.
2. Выберите интерпретатор **.venv\Scripts\python.exe**.
3. Запустите **main.py**. В браузере откроется **http://127.0.0.1:8000/**.

Зависимости установятся при первом запуске. Нужен установленный PostgreSQL 14+
(на этом компьютере обнаружен PostgreSQL 18). Скрипт создаёт отдельный кластер
в `.runtime/postgres`, на порту **55432**. Существующая служба PostgreSQL и её базы
не изменяются. Секреты генерируются локально в `.env`.

Для демонстрации с вымышленными вещами и участниками укажите в параметрах запуска
PyCharm `--demo` или выполните:

```powershell
.venv\Scripts\python.exe main.py --demo
```

На этом компьютере демонстрационная база уже подготовлена. Логины:
`coordinator`, `volunteer`, `donor`, `recipient`. Случайный пароль сохранён
в **.runtime/demo_accounts.txt**. Вход — кнопка «Войти» в шапке.

**Демонстрационная база прилагается в папке [demo](demo/README.md)**: SQL-снимок
PostgreSQL и данные для загрузки Django. Для первого запуска после клонирования
с приложенной базой используйте `python main.py --demo-db`.
Логины: `coordinator`, `volunteer`, `donor`, `recipient`; публичный учебный пароль
этой копии — `NordSecDemo2026!`. Существующие локальные записи и пароли не заменяются.

Демонстрационные аккаунты не являются администраторами Django. Создание
технического администратора при работающей локальной базе:

```powershell
.venv\Scripts\python.exe manage.py createsuperuser
```

Панель администратора — `/admin/`. Обычная работа координатора выполняется
в собственном кабинете. Получатель и жертвователь могут пользоваться одним аккаунтом.

Остановка локального приложения — **Ctrl+C** в окне запуска. Созданная база сохраняется.
`--port 8001` меняет порт сайта; `--no-browser` отключает автоматическое открытие браузера.
Не запускайте два экземпляра `main.py` одновременно с одной локальной базой.

## Подключение БД PostgreSQL

Запустить проект в PyCharm (`main.py`) → открыть pgAdmin → нажать правой кнопкой
на **Servers** → **Register → Server…** → во вкладке **General** указать
**Name: NordSec** → перейти во вкладку **Connection** и заполнить:

- **Host name/address:** `127.0.0.1`
- **Port:** `55432`
- **Maintenance database:** `nordsec`
- **Username:** `nordsec`
- **Password:** см. личку в ТГ.

Включить **Save password?** → нажать **Save** → раскрыть
**NordSec → Databases → nordsec → Schemas → public → Tables

## Что реализовано

- Регистрация, вход, выход, смена и восстановление пароля по почте, профиль; роли участника, волонтёра и координатора.
- Предложение вещи с фотографией; проверка и отклонение координатором с причиной.
- Каталог, поиск, фильтры, сортировка, избранное, постраничная навигация.
- Заявки посетителей на выбранные вещи; ручная запись обращений координатором; уточнение, одобрение, отказ, отмена.
- Резерв с ограниченным сроком; защита от двойного резерва на уровне транзакций и БД.
- Волонтёрские заявки и поручения: принятие, получение вещи, доставка, отказ до получения.
- Подтверждение фактической выдачи координатором; отдельное исправление ошибочной выдачи.
- Уведомления в кабинете, история действий и журнал координатора.
- Отчёт за период и CSV-выгрузка; исправленные выдачи исключаются из итога.
- Закрытые телефоны и адреса; фото проходят проверку и сохраняются без EXIF.
- Автоматическая проверка просроченных резервов раз в минуту при запуске через `main.py`.
- Резервное копирование базы и загруженных фотографий.

Одна карточка — одна вещь или неделимый комплект. Предложение до одобрения
не публикуется. Отметка волонтёра о доставке не заменяет подтверждение выдачи.
Вещь в пути не возвращается в доступный каталог автоматически при истечении резерва.

## Структура

```text
NordSec/
├── main.py                     # удобный запуск из PyCharm
├── manage.py                   # команды Django
├── config/                     # настройки, адреса, WSGI/ASGI, чтение .env
├── apps/
│   ├── accounts/               # пользователи, регистрация, профиль, роли
│   └── aid/
│       ├── models.py           # вещи, обращения, резервы, поручения, выдачи
│       ├── services.py         # операции и правила смены состояний
│       ├── forms.py            # формы и проверка ввода
│       ├── permissions.py      # доступ к собственным записям
│       ├── views.py            # обработка запросов и страницы
│       ├── urls.py             # адреса разделов
│       ├── migrations/         # воспроизводимая схема базы
│       ├── management/commands/# демонстрация и истечение резервов
│       └── tests/              # сценарии, доступ, конкуренция
├── templates/                  # HTML: accounts, aid, includes, errors
├── static/                     # css, js, brand, illustrations
├── scripts/                    # запуск, рабочий сервер, копии, логотип
├── docs/                       # архитектура, инструкция, размещение
├── demo/                       # приложенная демонстрационная БД и инструкция
├── requirements.txt            # зависимости
├── .env.example                # пример ручных настроек
├── .env                        # локальные секреты (не включать в Git)
└── .runtime/                   # локальная БД и демодоступы (не включать в Git)
```

## Проверка

```powershell
.venv\Scripts\python.exe main.py --test --no-browser
```

Команда использует отдельную тестовую базу PostgreSQL и затем удаляет её.
Демонстрационные записи остаются. Для ручных команд при уже запущенной базе:

```powershell
.venv\Scripts\python.exe manage.py check
.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.venv\Scripts\python.exe manage.py test apps --noinput
```
