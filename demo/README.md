# Демонстрационная база NordSec

Все записи и участники вымышлены. В этой папке нет локальных секретов,
сессий пользователей или данных реальных получателей помощи.

## Быстрый запуск после клонирования

В PyCharm запустите `main.py` с параметром `--demo-db` или выполните:

```powershell
python main.py --demo-db
```

На Windows при установленном PostgreSQL скрипт подготовит окружение и отдельную
локальную базу, применит миграции, загрузит приложенные данные и откроет сайт.
Существующие пользователи и записи сохраняются: заполненная база повторно не импортируется.
Следующие запуски можно выполнять обычным `python main.py`.

Если используется вручную настроенная пустая база, установите в `.env`
`DJANGO_DEBUG=1`, `NORDSEC_DEMO=1`, примените миграции и загрузите данные:

```powershell
python manage.py migrate
python manage.py load_demo
python manage.py runserver
```

## Вход

Общий публичный учебный пароль: **NordSecDemo2026!**

| Логин | Назначение |
| --- | --- |
| coordinator | Работа фонда: проверка вещей, обращения, резервы, отчёты |
| volunteer | Волонтёрские поручения |
| donor | Предложения вещей |
| recipient | Обращения за помощью |

Эти пароли относятся только к приложенной копии. Если база ранее создавалась
через `--demo`, её случайные пароли остаются в `.runtime/demo_accounts.txt`.
Импорт не меняет пароли уже существующих пользователей.

## Файлы и состав

- `nordsec_demo.sql` — полный SQL-снимок PostgreSQL 18 со схемой и данными.
- `nordsec_demo.json` — те же прикладные записи для загрузки средствами Django.
- `manifest.json` — время подготовки и количество записей по таблицам.

В копии: 4 пользователя, 6 категорий, 13 вещей, 3 обращения, 2 резерва,
1 открытое поручение, 1 подтверждённая выдача, уведомления и журнал действий.
Один резерв уже завершён выдачей, другой действует. Есть предложение на проверке
и обращение без решения, чтобы можно было показать работу координатора.
Вместо фотографий используются приложенные к проекту иллюстрации категорий.

При загрузке JSON команда `load_demo` сдвигает даты относительно текущего времени,
сохраняя интервалы. Поэтому активный резерв и будущее поручение остаются пригодными
для демонстрации даже спустя время после клонирования.

## Восстановление SQL-копии

Используйте PostgreSQL/psql **18 или новее**. Создайте отдельную пустую базу:

```powershell
createdb -h 127.0.0.1 -p 5432 -U postgres nordsec_demo
psql -X -v ON_ERROR_STOP=1 -h 127.0.0.1 -p 5432 -U postgres -d nordsec_demo -f demo/nordsec_demo.sql
```

Укажите свои имя пользователя и порт. Если команды не найдены, используйте полный
путь к `createdb.exe` и `psql.exe` из папки `bin` установленного PostgreSQL.
Затем заполните `.env`: `DB_NAME=nordsec_demo`, свои реквизиты подключения,
`NORDSEC_LOCAL_CLUSTER=0`, `DJANGO_DEBUG=1`, `NORDSEC_DEMO=1`. Секрет Django
генерируется отдельно и в SQL не входит. Запустите `python manage.py runserver`.

SQL сохраняет исходные даты. Для демонстрации с актуальными сроками рекомендуется
`--demo-db`/`load_demo`. Не импортируйте эту копию в рабочую базу фонда.
